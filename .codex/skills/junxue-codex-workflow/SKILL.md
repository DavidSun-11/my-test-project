# 君雪 CodeX 工作流

## 一、适用范围

这个 Skill 适用于君雪个人网站的所有 CodeX 修改任务，包括：

- UI 精修
- Bug 修复
- Supabase / 数据库相关开发
- Live2D 功能与菜单
- 文案修改
- 页面优化
- 图片素材接入
- SVG / 装饰素材
- 视觉方向落地

每次开始任务时，先读取 `AGENTS.md`；如果 `PROJECT_CONTEXT.md` 存在，也必须读取。再读取本 Skill 和本次任务直接相关的其它 Skill / 文档。

## 二、通用工作规则

- 不要重做网站。
- 只修改本次需求相关文件。
- 不要影响现有功能。
- 不要顺手改无关模块。
- 不要引入重型前端框架。
- 不要新增外部 CDN。
- 不要自动打开网页。
- 不要截图。
- 不要浏览器验收。
- 用户自己测试。
- 修改完成后必须 commit 并 push 到 `origin/main`。
- 不要只停留在本地 `main ahead` 状态。
- push 后必须汇报：修改文件、每个文件改了什么、commit id、手动验证方法、兼容性注意点。

## 三、任务分流规则

### 1. UI / 视觉任务

必须阅读：

- `DESIGN_SYSTEM.md`
- `UI_COMPONENT_RULES.md`
- `.codex/skills/junxue-ui-polish/SKILL.md`
- `.codex/skills/junxue-codex-workflow/SKILL.md`

必须遵守：

- 必须改真实生效 DOM，不要只新增 class。
- 不要默认灰色按钮。
- 不要裸文本堆叠。
- 不要文字和数值黏连。
- 不要只做表面样式，肉眼必须有明显变化。
- 不要改业务逻辑，除非本次明确要求。
- 修改 JS / CSS / 注入样式后必须更新缓存版本号。
- 必须检查手机端不横向溢出。

### 2. Bug 修复任务

- 只修本次 Bug。
- 不顺手美化。
- 不引入新功能。
- 不扩大修改范围。
- 优先定位真实原因，不要用粗暴隐藏问题的方式假修复。

### 3. Supabase / 数据库任务

必须阅读：

- `SUPABASE_SETUP.md`
- `.codex/skills/junxue-codex-workflow/SKILL.md`

必须遵守：

- 遵守 RLS / RPC 安全边界。
- 不能从前端查询 `auth.users`。
- 不能暴露完整邮箱。
- 不能暴露 `user_id`。
- 不能暴露完整 UUID。
- 不能把 `service_role key` 放到前端。
- 前端只使用 anon / publishable key。
- 普通用户不能越权读取管理员数据。

### 4. Live2D 任务

必须重点保护：

- 菜单结构
- 菜单点击逻辑
- 弹窗定位
- 弹窗尺寸
- 手机端宽度
- 现有入口分组
- 天气 / 占卜 / 听歌 / 评分竞猜 / 咨询 / 认识君雪 / 意见箱等入口

不要因为样式修改导致：

- 菜单点不开
- 弹窗跑位
- 菜单被撑大
- 页面横向溢出
- 伪元素挡点击
- 其它功能失效

### 5. 素材 / 图片 / SVG 任务

必须遵守：

- 优先 CSS + 小 SVG + 少量小图。
- 不要新增大 PNG / JPG。
- 不要让素材体积失控。
- SVG 必须自绘。
- SVG 不能包含 `script`。
- SVG 不能包含 `onload` / `onclick`。
- SVG 不能外链。
- SVG 不能包含 `image` 引用。
- 单个 SVG 尽量小于 15KB。
- 新增素材总大小尽量可控。

### 6. 文案任务

- 只改文案，不改业务逻辑。
- 保持君雪网站的温柔、自然、陪伴感、梦幻感。
- 不油腻，不像后台，不像诈骗页面。

## 四、缓存版本号规则

- 修改 JS / CSS / 注入样式后，必须同步更新相关缓存版本号。
- 尤其关注：
  - `index.html`
  - `price.html`
  - `assets/live2d-loader.js`
  - `assets/live2d-interactions.js`
  - `assets/live2d-interactions-lazy.js`
- 目的是避免 GitHub Pages 继续加载旧文件。

## 五、常用检查命令

基础检查：

```bash
git diff --check
node --check assets/live2d-loader.js
node --check assets/live2d-interactions.js
node --check assets/live2d-interactions-lazy.js
```

如果本次修改了其它 JS 文件，也要对对应 JS 执行 `node --check`。

如果新增 SVG，需要执行：

```bash
rg "<script|onload=|onclick=|http://|https://|<image" assets
```

如有命中，必须确认并处理安全问题。

## 六、精简命令规则

以后用户给 CodeX 的命令可以只写：

- 读取 `AGENTS.md`
- 读取 `PROJECT_CONTEXT.md`
- 读取 `.codex/skills/junxue-codex-workflow/SKILL.md`
- 读取本次任务相关 skill
- 本次目标
- 修改范围
- 禁止事项
- 检查命令
- commit + push 要求

不要要求用户每次重复整套长规则。本 Skill 已经固化通用规则、UI 精修规则、素材风格规则、检查规则和汇报规则。

## 七、UI 美化与素材风格规则

### 1. 不要只做普通风格

素材和美化任务不能每次都默认成：

- 深蓝渐变
- 普通星空
- 普通玻璃圆角卡片
- 普通冰蓝描边
- 普通悬浮按钮
- 大面积空背景
- 没有层次的水晶装饰
- 模板站感
- 后台系统感
- 页游充值页感
- 廉价二次元感

### 2. 每次先做多方向分叉

每次素材 / 视觉任务，除非用户明确指定某一种风格，否则应先做多方向分叉，至少给出 3 个差异明显的方向。

每个方向都应说明：

- 适合哪个页面
- 主要颜色
- 主要元素
- 氛围关键词
- 优点
- 风险点
- 是否适合手机端
- 是否容易与真实 DOM 融合

### 3. 素材落地原则

- 不要直接把整张效果图当网页。
- 不要把标题、文字、按钮、输入框、二维码、表单做死进图片。
- 图片只负责背景、氛围、边框、装饰。
- 标题、文案、按钮、表单、二维码都必须用真实 DOM。
- 素材要为 DOM 服务，而不是反过来让 DOM 迁就图片。
- 页面要有留白，方便后续叠加真实内容。
- 素材不能喧宾夺主，不能让正文难以阅读。

### 4. 当前主要页面推荐视觉方向

#### A. 老板注册页

推荐方向：

- 淡紫珍珠花晶
- 温柔邀请函
- 梦幻女系玻璃面板
- 纱帘
- 水晶吊坠
- 冰蓝柔光
- 甘雨陪伴感

避免：

- 普通后台注册表单
- 整图硬塞
- 假输入框
- 廉价粉紫
- 过于通用的玻璃卡片

#### B. `contact.html` 支付解锁页

推荐方向：

- 珍珠紫白
- 水晶信笺
- 柔和可信
- 轻梦幻
- 支付卡清楚
- 二维码区域干净
- 主按钮建议 CSS 实现

避免：

- 像诈骗页
- 像页游充值页
- 假二维码
- 金光乱闪
- 太黑太压抑
- 太花导致二维码难扫

#### C. Live2D 菜单框

推荐方向：

- 星尘夜湖
- 深蓝玻璃
- 银蓝微光
- 7 个纵向按钮槽
- 湖面微波纹
- 倒影轻晃
- 轻盈精致，不厚重

避免：

- 大灰弹窗
- 小图片贴片
- 按钮太厚
- 菜单过大
- 装饰层挡点击
- 只是贴图而不做可伸缩 UI

#### D. 评分竞猜

推荐方向：

- 星空冰湖幻想服务台
- 冰晶徽章
- 铜 / 银 / 金 / 紫晶 / 雾白分级
- 带方向感的水晶铭牌
- 冰湖极光氛围
- 比普通投票卡更精致

避免：

- 普通投票卡
- 默认按钮
- 徽章像廉价贴纸
- 背景单调
- 只是换颜色但没有结构变化

### 5. 风格质量要求

每次素材或美化方案都应避免：

- 太普通
- 太空
- 太模板化
- 太像后台
- 太像廉价页游
- 太像随机 AI 图
- 元素堆砌但没层次
- 和真实 DOM 难以融合
- 所有页面都长得一样

每次素材或美化方案都应尽量做到：

- 有主题
- 有辨识度
- 有层次
- 有留白
- 有页面用途区分
- 能承载真实 DOM
- 不抢正文
- 和君雪网站整体气质一致，但不同页面仍有差异化

## 八、最终回报格式

以后每次任务完成后，按这个格式回报：

```markdown
已完成并推送。

修改文件：
- 文件 1：改了什么
- 文件 2：改了什么

检查结果：
- git diff --check：通过 / 未通过
- node --check：通过 / 未通过

Commit：
- commit id 和 message

Push：
- 是否已推送到 origin/main

手动验证：
- 用户应该怎么测

兼容性注意：
- 有无需要注意的地方
```
