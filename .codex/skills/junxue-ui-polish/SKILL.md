# 君雪网站 UI 美化 Skill

## 什么时候使用

当用户提出以下需求时使用本 skill：

* 美化页面
* 美化弹窗
* 美化按钮
* 美化菜单
* 美化投票卡
* 根据截图或参考图调整 UI
* 用户说“太丑”“太单调”“布局不好看”“框不好看”
* 用户要求保持君雪网站风格

## 必须先阅读

在开始任何 UI 修改前，必须先阅读：

1. `DESIGN_SYSTEM.md`
2. `UI_COMPONENT_RULES.md`

## 核心风格

必须保持：

* 深蓝星空
* 冰蓝玻璃
* 淡紫柔光
* 幻想感
* 甘雨陪伴感
* 温柔但高级

禁止：

* 默认浏览器灰色按钮
* 大块纯黑弹窗
* 文字和数值黏在一起
* 按钮散落
* 没有层级的裸文本
* 手机端横向溢出
* 文字竖排
* 投票选项像调试按钮

## 修改流程

1. 先确认本次是 UI 修改，不是业务逻辑修改。
2. 找到真实生效的 HTML/DOM 渲染路径。
3. 找到真实生效的 CSS/class。
4. 不要只新增备用 class，必须让实际页面用上新结构。
5. 保留原有功能事件绑定，例如 data-action、data-score-choice、data-score-action。
6. 只改与本次 UI 相关的文件。
7. 如果修改 JS/CSS 且线上可能缓存，必须更新资源版本号。
8. 修改完成后执行检查命令。
9. commit 并 push 到 origin/main。

## 弹窗与面板规则

弹窗必须优先采用：

* header
* content / meta
* card grid
* actions
* footer note

不要把文字、按钮、选项随意堆在一起。

## 按钮规则

按钮必须区分：

* 主按钮
* 次按钮
* 返回按钮

禁止使用默认灰色按钮。
disabled 状态也要可读，不允许灰成一团。

## 投票卡规则

投票选项必须做成卡片，不是普通按钮。
每张投票卡应包含：

* 徽章或图标
* 标题
* 人数
* 选中态
* hover / active / disabled 样式

## 手机端规则

手机端必须：

* 不横向溢出
* 不文字竖排
* 面板 max-width 使用 92vw 或 calc(100vw - 32px)
* 内容多时内部滚动
* 关闭按钮不被遮挡
* 点击区域不小于 40px

## 检查清单

UI 修改完成后必须检查：

* 是否遵守 DESIGN_SYSTEM.md
* 是否遵守 UI_COMPONENT_RULES.md
* 是否没有改业务逻辑
* 是否没有破坏原有事件绑定
* 是否没有默认灰色按钮
* 是否手机端不横向溢出
* 是否更新缓存版本号
* 是否执行 git diff --check
* 如果修改 JS，是否执行 node --check

## 最终回复要求

完成后必须说明：

1. 修改了哪些文件
2. 是否只新增 skill 文档
3. 是否没有改功能代码
4. 以后什么场景会使用这个 skill
5. commit id
6. push 是否成功
